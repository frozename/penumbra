# Source extraction labels, frozen before model development

Evaluate useful durable memory, not agreement with an incumbent or historical retention. Candidates are captured agent prompts/responses; the rendered `User:` label alone does not prove a direct human instruction.

Eligible content includes explicit persistent human preferences, project decisions with stated rationale, and non-obvious empirical/domain pitfalls with a supported explanation or workaround. A runtime lesson may mention code; a configuration inventory, file location, identifier, one test result or implementation status alone is ineligible. Reproducing an empirical behavior is different from reading a constant in source.

Exclude quoted/pasted prompts, role briefs, task-only constraints, plans not established as decisions, retracted claims, invented causes/remedies, and unverified historical execution/timing. A genuine persistent preference is not automatically an excluded agent role brief. Current code and isolated reproduction can corroborate a mechanism; they cannot prove a historical production run.

Textual support and policy eligibility are separate labels. Exact quotes do not establish factual truth. Any material claim in a proposed memory must be supported, including rationale, scope, versions and metadata. Preserve uncertainty and narrow version/context qualifiers. Do not approve a useful core together with unsupported extra claims.

Each positive source case requires independently checked facts, exact source quotations and concrete primary-source checks or explicit limits. Negative cases require reasons. Uncertain cases stay uncertain. Up to three expected facts per case; identify related lesson families so train/development/test families cannot silently overlap.

The following exposed development families are excluded from new historical test positives: retention LIMIT versus sparse scan work; Bun/SQLite FTS changes overcount; root-versus-attempt efficacy aggregation; benign ONNX teardown panic; missing composite build artifacts; comparator orientation in the prior quality studies.

This is purposive positive enrichment and adversarial evaluation, not a population-random sample or proof of a production error-rate bound. Store source text and labels privately. Do not reveal held-out bodies or substantive labels to the implementation agent until its candidate policy and code are frozen. Stored memory membership is sampling enrichment only, never truth.
